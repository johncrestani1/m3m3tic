# Contributing

## How to Contribute

### Reporting Issues
- Use GitHub Issues for bugs in the spec, schema, or examples
- Include the spec version you're referencing
- For compliance rule suggestions, include the regulation citation

### Proposing Spec Changes
1. Open an Issue describing the change and its rationale
2. Reference any relevant standards (DTCG, OSCAL, C2PA, FTC guidelines, etc.)
3. Include a YAML example showing the proposed syntax
4. Wait for maintainer feedback before submitting a PR

### Submitting Pull Requests
- One change per PR
- Update the spec, schema, AND examples together (they must stay in sync)
- Add test cases in `tests/valid/` or `tests/invalid/` as appropriate
- Update CHANGELOG.md

### What We're Looking For
- New compliance rule packs (industry-specific, jurisdiction-specific)
- Additional example `.m3m3tic` files for different industries
- Improved JSON Schema constraints
- Spec clarifications and edge case documentation

## Code of Conduct

Be professional. Be constructive. Focus on the work.
